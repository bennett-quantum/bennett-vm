## Confirmed defects, most severe first

### D1. `measure.iN` is invisible to the reversal machinery — bennett-vm-4ke (P1)

- Where: [cc.rs](/home/tobias/Projects/bennett-workspace/bennett-vm/src/cc.rs:684)
  `measured: ins.op == "measure"`, and the same exact match in the launch
  runtime's random-draw injection at
  [cc.rs](/home/tobias/Projects/bennett-workspace/bennett-vm/src/cc.rs:2106).
  For the 0.9 form `measure.iN`, `ins.op` is `"measure.iN"`, so the history
  frame is never marked measured.
- Spec: §3.3 (`measure.iN` on a `qreg[n]` with N = n is the same
  instruction), §7.4 (a segment containing a `measure` frame cannot be
  uncalled; illegal uncall is a trap with no state change beyond the fault
  record), §10 reverse eligibility and §14.3 T4.
- Witness: `.tmp/review-cc/probe/objs/measure_in.bisa` (Bell action,
  `r = measure.i2 q`, then `call`/`uncall` chain, generated by the probe).
  - Expected: `run-cc bad_uncall` → FAILED, fault 4; `reverse measuring`
    → `E_NOT_REVERSIBLE`.
  - Actual: both exit 1 with the hard diagnostic
    `§7.4: inverse left a released wire unclean` — the uncall/reversal was
    permitted, ran the adjoint over the collapsed state, and aborted
    mid-undo with no fault record.
  - Control: the identical object with plain `measure` traps 4 and refuses
    reversal correctly (VM and `bennett-isa-ref` agree). The reference
    binary does not yet accept `measure.i2`, so the .iN expectation rests
    on the spec text plus this control.
- Red test: `measure_in_blocks_uncall_and_reversal` in
  `.tmp/review-cc/probe/tests/probe.rs`.

### D2. CC region calls never check run-time wire overlap — bennett-vm-3tx (P1)

- Where: [cc.rs](/home/tobias/Projects/bennett-workspace/bennett-vm/src/cc.rs:1094)
  `Machine::region` resolves the qreg operands and applies the invocation
  with no pairwise-disjointness check over the mut/in/tgt/fr/mem/control
  wire sets. The action entry checks only the designated idle set
  (`execute_action_with_idle`), and the oracle branch enumeration checks
  nothing.
- Spec: §3.3 region-call ledger row and "Registers, handles and aliases" —
  the wire operands of one region call, with its effective control context,
  must be pairwise disjoint; any overlap not rejected statically (aliases
  created by `call` transfers are the given example) is a CC trap /
  R fault `FAULT_UB_TRAP` before any effect. §4.9: the failing instruction
  has no effect beyond the terminal fault record.
- Witness: `.tmp/review-cc/probe/objs/alias.bisa` — `main` toggles `q` to
  |1⟩, then `call @g q q`; `@g` runs `action_call @cxact (a) (b)` whose body
  is `cx c t`, so the control wire is the target wire; then `measure q`.
  - Expected (and `bennett-isa-ref`): FAILED, fault 4, no measurements.
  - Actual (VM, both engines): COMPLETED, measurement 0. The
    self-controlled flip is not unitary; in superposition the two branches
    would merge and amplitudes add.
- Red test: `aliased_region_call_traps`.

### D3. FAILED runs cannot reverse via `run-program` / `bennett_reverse` — bennett-vm-w63 (P1)

- Where: [cc.rs](/home/tobias/Projects/bennett-workspace/bennett-vm/src/cc.rs:1568)
  (`Mode::Program` returns `E_INVALID_STATE: cannot reverse a FAILED run`)
  and `src/launch.rs:672` (`bennett_reverse` requires COMPLETED).
- Spec: §10 state machine has `FAILED → REVERSED`; reversal first undoes
  the terminal fault record (K6; §14.3 T4 eligibility is "COMPLETED or
  FAILED"). The traversal itself already works: the `reverse` CLI
  (`Mode::Reverse`) and `Runtime::reverse_to` (which
  `bennett_run_reverse_to` exposes for FAILED runs, launch.rs:1042) both
  reverse failed runs.
- Witness: `.tmp/review-cc/probe/objs/boom.bisa` (`udiv` by zero).
  - `bennett-vm reverse boom` → REVERSED, `equals_entry:true` (agrees with
    the reference). 
  - `bennett-vm run-program boom --reverse` → exit 1,
    `§10: E_INVALID_STATE: cannot reverse a FAILED run`; the reference
    gives REVERSED with `reversed:true`.
- Red test: `failed_run_reverses` (the run-program assertion).

### D4. `QuantumState::measure` rebuilds the exact map from f64 — bennett-vm-p5i (P2)

- Where: [action.rs](/home/tobias/Projects/bennett-workspace/bennett-vm/src/action.rs:224)
  `measure()`: probabilities from the binary64 cache, collapse and
  renormalisation `1/sqrt(p)` in f64 (lines 244–255), then
  `self.exact` is rebuilt from the f64 amps via `Exact::pair`
  (lines 256–260).
- Spec/contract: §14.2 (post-measurement state is the exact renormalised
  projection) and this crate's own header contract
  ([action.rs](/home/tobias/Projects/bennett-workspace/bennett-vm/src/action.rs:1),
  [exact.rs](/home/tobias/Projects/bennett-workspace/bennett-vm/src/exact.rs:1)):
  exact amplitudes determine support, cleanliness and equality; no epsilon
  enters any of them. `exact_equals` is load-bearing
  (`src/qcli.rs:278`, `src/certificate.rs:352`).
- Witness (unit, probe `measure_preserves_exact_state` variant B): H on two
  wires, measure the first with draw 0. Post-state amps are
  `0.7071067811865475` per branch, squared norm `0.9999999999999998`, and
  `exact_equals` against the identical |0⟩|+⟩ state built without
  measurement is `false` — the symbolic √(1/2) was replaced by an f64
  dyadic, for every wire of every register measured from then on.

### D5. `qinplace` full form is admitted but can never execute — bennett-vm-32m (P2)

## Plausible, not confirmed (no bead)

- **PLAUSIBLE — `measure.iN` run-time width trap missing in CC exec.**
  [cc.rs](/home/tobias/Projects/bennett-workspace/bennett-vm/src/cc.rs:991)
  measures all wires of the handle, never compares the `.iN` suffix to the
  register width, and returns `Value::int(ws.len(), v)`. For a `qreg[n]`
  the static check in typing covers it; the dynamic case (spec §3.3
  example: `measure.i3` of a width-2 `qreg[*]` must trap before measuring,
  consuming no draw) is reachable today only through launch-supplied
  `qreg[*]` parameters, because CC-level `qreg[*]` creation
  (`qreg.new` with an `i64` count, run-time `qreg.slice` length,
  `qreg.width/id/from_id`) is still unimplemented under the bennett-vm-47t
  umbrella. No execution witness was built, so this stays PLAUSIBLE; it
  should be fixed together with D1.
- **PLAUSIBLE — partial application when a Q execution errors.**
  `exec_oracle_call`
  ([action.rs](/home/tobias/Projects/bennett-workspace/bennett-vm/src/action.rs:1229))
  runs the oracle inside `map_basis`; on a `run_oracle` error the branches
  already transformed stay transformed and the call returns Err with the
  state mutated and no history frame. The same shape exists for action
  bodies generally (only the target/request path executes on a trial
  clone, `execute_action_with_requests`) and for `Machine::undo` if an
  inverse invocation fails midway
  ([cc.rs](/home/tobias/Projects/bennett-workspace/bennett-vm/src/cc.rs:451)).
  Every `run_oracle` Err found by inspection is a static width/shape
  re-check that validated objects should never trigger, so no
  input-dependent witness could be constructed. D1's crash shows the
  mid-undo abort is reachable once a frame is wrongly marked reversible,
  but its root cause is D1.
- **PLAUSIBLE — outcome selection vs the §4.1 total-weight rule.**
  `measure()` selects by `draw < cumulative` over unnormalised f64
  probabilities and falls back to `probs.keys().last()` (numerically
  largest, not lexicographically last) if the cumulative sum is exhausted.
  §4.1/K17 define selection against `draw × total weight`. With exact
  states the total is 1 up to f64 rounding of `Exact::value()` (which also
  truncates rather than rounds in `Dyad::value`,
  [exact.rs](/home/tobias/Projects/bennett-workspace/bennett-vm/src/exact.rs:90));
  no draw was found that reaches the fallback through the CLI.
- **Minor, code-evident only.** `Exact::rotation` maps any unknown axis to
  the rz matrix ([exact.rs](/home/tobias/Projects/bennett-workspace/bennett-vm/src/exact.rs:199));
  both callers guard on `rx|ry|rz`, so it is unreachable, but it is the
  opposite of fail-fast. `Exec::angle` falls back to `f64::INFINITY` for an
  out-of-range integer argument
  ([action.rs](/home/tobias/Projects/bennett-workspace/bennett-vm/src/action.rs:424)),
  which would panic in `Dyad::float` if a validator ever let it through.
  `record_quantum` cancellation compares `Value`s, so a NaN f64 classical
  argument would never cancel and would make a perfectly reversed run
  report a quantum first-difference.

## Areas that look right, with the evidence

- **K17 draw order.** Probe `k17_draw_order` passes: two two-wire H
  registers with draws `0.25,0.75` give bits `01`,`11` (values 2,3),
  including the exact-CDF-tie behaviour; VM and reference identical.
  FIFO consumption and wire-0-first lexicographic order in
  `QuantumState::measure` match §4.1. Unsupplied draws default to 0.0 in
  both CLIs (checked three runs each), so that is an agreed CLI
  convention, not a divergence.
- **Plain `measure` reversal blocks.** Segment `uncall` over a plain
  measurement traps 4 and whole-run reversal returns E_NOT_REVERSIBLE;
  VM and reference agree (probe control in D1's test).
- **FAILED-run reversal traversal itself.** `reverse` on the faulting
  `boom` object restores entry state (`equals_entry:true`), agreeing with
  the reference; D3 is only about the two gates that refuse to call it.
- **`uncall` after an intervening uncalled segment.** My initial reading
  was that the purity test at cc.rs:893 should ignore already-reversed
  frames; the reference traps identically (fault 4) on the probe object
  `uncall2.bisa`, so the VM matches the reference here. Not a defect.
- **Controlled quantum semantics and exact cancellation.** Predication is
  branch-exact (`apply_exact`/`map_basis` skip branches whose controls are
  not all 1; oracle calls are branch-enumerated under the predicate with
  outcomes memoised on the projected `(ins, mem cells)` key, which is the
  full input the permutation depends on for a fixed callee/args/budget —
  target and fault registers correctly enter only as XOR destinations).
  The repo's own `tests/coherent.rs` passes 10/10 at the pinned commit
  (borrowed-wire identity on an entangled reference, exact H² support,
  rotation-inverse workspace clearing, step-prefix reversal), and the
  `exact` unit tests pass (symbolic rotation inverses cancel exactly,
  including the `f64::MAX` angle display guard).
- **Effect/tape handling in `step_row`** validates replay before commit
  and restores the checkpoint on a replay error; device effects validate
  ranges before any mutation (cc.rs `effect()`), matching §7.3 atomicity
  on inspection. Not independently probed beyond the repo tests.
